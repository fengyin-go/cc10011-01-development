# 采集调度策略管理工具

离线版采集调度策略配置工具，涵盖站点登记、模板编排、代理轮换、限速调节、反爬策略、增量水位与结果校验规则，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/domain/           激活核验领域层（纯函数引擎，可独立单测）
│   │   ├── types.ts          准入记录/负责人台账/待处理清单/审计/越权证据类型
│   │   ├── engine.ts         域名加工、数据准入、去重归并、双负责人状态核验
│   │   └── intake.ts         模板编排落点同步、冲突判定、可引用站点候选
│   ├── src/views/            每个业务模块一个页面（含 admission 准入数据集页）
│   ├── src/api/
│   │   ├── local-service.ts      通用模块本地数据服务
│   │   └── admission-service.ts  激活核验服务：权限边界、原子提交、越权留证
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/session.ts 会话角色（值班管理员 / 站点负责人）
│   └── tests/                node:test 行为测试与 esbuild 测试运行器
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

测试（领域引擎 10 例 + 服务层集成 8 例，零浏览器依赖）：

```bash
cd frontend
npm test
```

## 站点激活核验与采集站点准入数据集

站点登记不再只有状态按钮，激活走一条可核验的数据流：

```text
站点登记(site)
  -- 读取 域名地址/请求方式/字符编码/请求头模板/站点负责人 -->
核验引擎 engine.ts（数据准入 + 域名去重归并 + 提交时/当前负责人双快照）
  -- 原子提交 commitBundle（站点底表与准入结果要么一起生效，要么一起退回待校验）-->
采集站点准入数据集(siteAdmission，每站点仅一个当前准入版本，拒绝原因永久可回查)
  -- 模板编排待处理清单接收后再同步 --> 模板/任务编排的可执行站点底表
```

关键业务规则：

- **数据准入与去重**：域名加工为规范主机名（去协议/端口/路径/锚点、小写），同域名只保留一个当前准入版本，其余标记「已归并」并保留来源。
- **双负责人状态**：同时快照提交时归属与当前归属。提交时负责人停用或不在台账 -> 拒绝；在职但已不归属该站点 -> 「等待当前负责人重新确认后激活」，形成两套站点生效时间，但底表只留一个完整版本。
- **拒绝原因留痕**：拒绝/归并原因以来源链（`rejectionTraces`）只追加不清空；负责人失去站点归属后，原拒绝原因仍留在准入记录里，不会只剩无来源状态。
- **原子提交与回滚**：站点底表与准入 bundle 同一次 `commitBundle` 写入；任一键失败即回滚内存缓存、磁盘保持旧值，登记退回「待校验」。页面提供「模拟落盘失败」按钮演示。
- **模板落点与冲突**：待处理清单接收数据集后再同步，先核对「按提交时负责人状态完成激活」；站点登记处理失败时沿用上一份确认版本并留存当天轨迹；检测到「等待当前负责人重新确认」另一套边界时落「冲突待复核」，由值班管理员按提交时负责人状态复核，准入数据集供复核。
- **受控归属与越权证据**：站点负责人只能核验受控归属站点，越权请求被拒绝并写入只读证据（`accessDenials`，不可编辑/删除）。
- **可引用候选**：模板预设新版本、任务编排选择目标站点时，只有 `admitted` 当前版本进入候选，未准入站点不出现。

存储键：通用模块 `scraper-strategy-studio:entries`，准入核验域 `scraper-strategy-studio:admission-domain`。

| 任务编排 | `spider` | 采集作业 | 作业编号、目标站点、抽取模板 |

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `scraper-strategy-studio:entries` 这一项，或调用 `resetModule(模块)`。
